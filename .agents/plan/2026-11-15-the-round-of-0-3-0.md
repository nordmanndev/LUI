- **Base branch:** `0.3.0` — branched from `main` at `f4ef3c4` (the merge of the release of 0.2.0), with the three state

- **Decided by:** the owner, on 2026-11-14 and 2026-11-15 — every decision of the round is in the epic

- **Issues:** #169 (ADR-0066), #170 (ADR-0067), #171 (ADR-0068), #172 (ADR-0069), #173, #174, #175, #176, #177, #178,

- **Why now:** 0.2.0 is released (2026-11-15). The owner decided: **the next version is 0.3.0, and nothing else comes
  into it.**

## 1. The goal

**0.3.0 — the catalogue owns the connection.** The catalogue takes a file path and typed options, the method says what
the open may do (`Open`, `OpenOrCreate`, `OpenReadOnly`), the read path opens read-only, and the findings of the audit of
2026-11-13/14 are fixed. The public API breaks in named places; the freeze of ADR-0026 is lifted for this version by
ADR-0069 and holds again from 0.3.0 on.

The issues carry the whole decision, the measurements and the acceptance criteria. **The issue is the task**: a pull
request of this round does what its issue says, and where the issue and this plan disagree, the issue wins.

## 2. The rules of the round

1. **The branch of the round is `0.3.0`.** Every pull request of the round branches from `0.3.0` and targets `0.3.0` —
   not `dev`, not `main`.
2. **One pull request per issue**, in the order of §3. A pull request does not start before the one before it is merged
   (the later ones build on the earlier ones — the path, the methods of the open, the pragmas).
3. **Nothing else comes into 0.3.0.** No issue outside the list above, no fix in passing, no new feature. A finding on
   the way gets an issue of its own and waits for the round after; it does not ride along.
4. **Red first, inside every pull request.** The red commit is pushed first, its run is read, and then the fix is pushed
   (the CI cancels a run that a newer push overtakes: `cancel-in-progress: true`). The red commit stays in the history of
   the branch.
5. **Every pull request carries its own record and its own migration lines.** The record of the issue (ADR-0066 …
   ADR-0069) goes into `.agents/adr/` in the pull request of its issue, with its row in the index. Every pull request that
   breaks the public API writes its lines of the migration note into the section `## [Unreleased]` of `CHANGELOG.md`, and
   moves `docs/api.md` with the code.
6. **The branch of 0.3.0 is not releasable before #172 is merged** — the record that lifts the freeze, and the guard
   that the old API is gone. That is on purpose: the pull requests before it break the API inside the round, and the round
   is released as a whole.
7. **The numbers of the records are 0066–0069.** Before the first pull request, read the index of the records: if a
   record came in after 2026-11-15, the numbers move, and the issues, the epic and this plan move with them.
8. **The branch names** follow the series: `<type>/<issue>-<what-it-does>`, e.g. `feat/169-the-catalogue-takes-a-path`.
   Merged with a merge commit, as the series does.
9. **The open issues of the round before** — #165 (the file and the line of the one-off) and #192 (the window of the unit
   layer) — are **not** in 0.3.0. #192 can turn the Windows lane red on any pull request of the round: the lane is run
   again once, and if it is red again, the failure is real and is read, not waved through.
