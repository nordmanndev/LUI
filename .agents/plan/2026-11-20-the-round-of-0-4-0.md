  the freeze comes with 1.0.0, and the round of 0.4.0 is the one that rebuilds it.

## 1. The goal

**0.4.0 — the index names its type and its format.** The application names the type of the payload of an index once. The
index carries that type into the writing and into the reading. The format of the payload is bound to the type, not to the
catalog. And the typed hit carries the payload, so the application reads it like a field.

The public API breaks in named places. ADR-0072 lifts the freeze of ADR-0069 §4: from now on the API may break until
1.0.0, and every break gets a migration line and a record of its own. The file keeps no type name and no format name
(ADR-0035 §6 holds).

The issues carry the whole decision and the acceptance criteria. **The issue is the task**: a pull request of this round
does what its issue says, and where the issue and this plan disagree, the issue wins.

## 2. The rules of the round

1. **Every pull request of the round branches from `dev` and targets `dev`** — not `main`. The release is the pull request
   `dev` → `main`, with its own review.
2. **One pull request per issue**, in the order of §3. A pull request does not start before the one before it is merged —
   the later ones build on the earlier ones (the register, the renames, the property).
3. **Nothing else comes into 0.4.0.** The client series (#212) and the alignment with the Nordmann standards (#221) are not
   in it. #221 follows the round in the same milestone. A finding on the way gets an issue of its own and waits for the
   round after; it does not ride along.
4. **Red first, inside every pull request.** The red commit is pushed first, its run is read, and then the fix is pushed
   (the CI cancels a run that a newer push overtakes: `cancel-in-progress: true`). The red commit stays in the history of
   the branch.
5. **Every pull request carries its own record and its own migration lines.** The record of the issue (ADR-0072 …
   ADR-0075) goes into `.agents/adr/` in the pull request of its issue, with its row in the index. Every pull request that
   breaks the public API writes its lines of the migration note into the section `## [Unreleased]` of `CHANGELOG.md`, and
   moves `docs/api.md` with the code.
6. **The numbers of the records are 0072–0075.** ADR-0071 belongs to the record of the client — the plan of 2026-11-16,
   and the pull request #256 that corrects its number. Before the first pull request, read the index of the records: if a
   record came in after 2026-11-20, the numbers move, and the issues, the epic and this plan move with them.
7. **The branch names** follow the series: `<type>/<issue>-<what-it-does>`, e.g. `feat/260-the-register-of-the-payload-types`.
   Merged with a merge commit, as the series does.
8. **The round may break the public API** (ADR-0072): every break names itself in the CHANGELOG, moves `docs/api.md`, and
   gets a record of its own. The freeze of ADR-0069 §4 does not hold until 1.0.0.
